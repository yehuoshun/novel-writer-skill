> 何时加载：门禁与交付前检查全过之后（或 `publish-chapter.js` 发布时）。语雀 / 双写模式同时配合 [references/integrations/yuque-integration.md](../../integrations/yuque-integration.md)。

## 阶段四：落地 + 状态回写

> ⚠️ **改版备份铁律（2026-10-12 老板定）**：正文任何版本改动（朱雀迭代 / 复核修复 / 润色重写）**开始前**，先把**当前版全文**留档（本地：`novel/<书>/版本备份/` 下存 `ch{NNN}-v{版本号}.md`，并更新 `ch{NNN}-版本备份索引`：版本表 + 检测值 + 状态；语雀/both：存语雀「正文版本备份」分组，见手册 6.9）。v4.1 全文因未备份而不可考（教训：反复覆盖后无法溯源）。

17. 门禁全部通过后 → 落地（按 save_location）：
    - **本地模式（主线）**：正文存**完整版（含 CHANGES 块，工作态）**到 `local.content_path`；CHANGES 以正文内嵌块为权威，`设定/changes/` 目录**可选**（旧布局兼容：backup-snapshot 快照优先读 changes/chXXX.md，无则从正文提取归档）
    - **语雀 / 双写（both）模式**：上传前预处理（`prepare-upload.js` 剥离 CHANGES + 占位注释 + 缩进校验）→ 创建+挂载正文 DOC，全程细节（含 2026-10-09/11/12 语雀渲染与挂载踩坑记录）见 [references/integrations/yuque-integration.md](../../integrations/yuque-integration.md) 第 6 节
17.5. **双写对账（both 模式，2026-10-12 补）**：本地/语雀档案同步前后跑 `node scripts/yuque-doc.js audit --book <id> --local <小说目录>` 验证两侧一致（🟢 一致 / 🔴 本地有语雀无 / 🔵 语雀有本地无）；不一致先处理再进下一步。加 `--json` 可得结构化结果；书里还没建「正文」分组时，正文档会被逐条点名而不是让脚本崩掉（详见手册第 7 节）
17.6. **全书体检（跨章口径，2026-11-13 补）**：单章门禁只管这一章，**看得见单章、看不见全书**的毛病得过几章才显形——爽点连续断档、同一类型用腻、章尾钩子连着几章都软、情绪连着几章都平、字数越写越短、伏笔埋久了不动、角色消失太久。每写完 5–10 章（或每卷收尾）跑一次 `node scripts/book-report.js <config.json>`：读现成的爽点追踪 / 钩子追踪 / 情绪曲线 / 细纲 / 状态快照 / 正文，把上面几条一次算完并在屏幕上点名（红线 exit 1）；`--write` 落成 `设定/全书体检.md`，`--json` 给结构化结果。判据就是本文件里已经写死的那些（每 3000–5000 字一个爽点、连续 2 章无爽点、同类型连用 3 章、章尾无钩、连续 3 章弱、情绪极值连续 3 章 ≤5、连续 5 章 ≥8、反转差 ≤2、埋设 10 章未推进、字数下限），脚本不另立标准；它只报告不改稿，改不改由人定。字数一律按**发布账本**（`设定/changes/chNNN-publish.json` 的 `metrics`）记的那一版算——那才是读者拿到的；正文发布后被手改过，会另出一条黄条「发布后改稿」把「发布时多少字 / 现在多少字」并排给出（差异 <2% 不算，正常精修不动这条）。
    - **热度得人喂**：平台后台的追读/留存脚本看不到，用 `node scripts/chapter-heat.js <config.json> set <章号> --heat <数> [--retain 62%] [--note 备注] --write` 记进 `设定/章节热度.md`，体检会多出「低热度连片」（连续 3 章不到均值一半）与「爽点与热度」（有爽点的章平均热度反而更低 → 爽点雷同或位置不对）两条；标注不满 3 章不算。CI/日报：`--brief` 一行摘要、`--digest` 往 `设定/体检日报.md` 追加一行、`--fail-on warn` 让黄条也 exit 1（默认只有红线算失败）。
    - **挂进 CI**：把 [examples/github-actions/book-report.yml](../../../examples/github-actions/book-report.yml) 复制到小说仓库的 .github/workflows/，改两个 TODO（技能仓库 owner/repo、配置文件路径）——之后每次 push 正文或追踪档就自动跑一遍，一行简报写进 Actions Summary、完整报告作为 artifact 下载，红线直接让 job 失败；本地跑同一条命令即可（--brief / --write / --digest）。
18. **从 CHANGES 块提取变更**，自动更新设定：
    - **结构化那半可以交给脚本（v3.5.32）**：`node scripts/apply-changes.js <config.json> <本章正文.md> --write` 按 CHANGES 直接改 `状态快照.md`——角色状态与移动、伏笔四态、地点/势力、物品归属、冲突进度、时间线、整段交接包；**默认 dry-run**（只打印将改哪几行），重复跑幂等，快照里没登记的伏笔 ID 直接报错不猜。`publish-chapter.js --apply-changes` 则是发布成功后自动跑一遍。脚本碰表格与交接包，**并在同一趟同步伏笔档案**（`伏笔追踪/vID-*.md` 的 `- 状态：`、`- 埋设章节：`、`- 推进章节：`、`- 揭晓章：`，v3.5.35；档案不存在只提醒不新建）——7 个追踪文档、语雀侧 DOC 仍要按下面手工补。
    - **档案骨架也能机械建（v3.5.34）**：`node scripts/scaffold-entity.js <config.json> <草稿.md> --write` 按本章 CHANGES 把缺的**角色/地点/物品/势力档案**与「新埋设」的**伏笔档案**补出骨架，已有文件一个字节不动（默认 dry-run）。发布时加 `--scaffold` 就在门禁之前跑一遍——新角色上场前不建档，门禁 1 会拿「未登记实体」拦你。骨架只补字段（`身份：待补`、外貌段留空），内容还得自己填；**推进/回收没建过档的伏笔不补建**，直接报错（补建等于把漏建档洗成刚埋设）。
    - 更新 `状态快照.md`（当前态覆盖，非追加）
      - 本地模式：覆盖 `设定/状态快照.md`
      - 语雀 / 双写模式：两处都更新（语雀侧更新 `snapshot` 分组 DOC，见手册 6.5）
    - **覆盖 `## 下章交接包` 整段**（旧包作废）：从 CHANGES 的 `<!-- 交接包 -->` 声明生成，供下一章读取
    - **按伏笔状态机更新伏笔状态表**：🔨埋设→新增行（已埋设）**并创建 `伏笔追踪/vX-伏笔名.md` 文档**（含类型/预期读者效果/线索，与快照同步——漏建会导致下一章推进被门禁误拦「未登记伏笔」）；➡️推进→状态改已推进+追加推进章；✅回收→状态改已回收+写揭晓章；❌废弃→状态改已废弃
      - ⚠️ **伏笔档案回写铁律（2026-10-11 第11章复检固化）**：推进/回收/废弃时，`伏笔追踪/vX-*.md` 档案的**状态字段 + 推进记录**必须与快照伏笔表同步更新（本次 v1 快照已改「已推进」、档案还停「已埋设/待推进」，复检才抓到）。检查口径：回写后 grep vX 档案状态字段 ≠ 快照状态即漏
    - **CHANGES 归档**：本地模式**不另存 changes 文件**（正文完整版内嵌块为权威；旧书若已有 `设定/changes/` 目录，backup-snapshot 兼容读取，见阶段四 17 条）；语雀/both 模式归档到语雀「变更记录」分组（chXXX-changes 文档，编号三位零填充，永久保留），两步建 DOC 细节见手册 6.6
    - 更新各角色/地点/物品/势力/伏笔设定文档（双写模式两处都更新）
    - **更新追踪分组（2026-10-12 补，防再漏）**：每章回写必须同步 7 个追踪文档（本地 设定/爽点追踪、钩子追踪、情绪曲线、时间线、等级体系、世界观、关键对话）——从本章摘要/CHANGES 提取爽点类型、首尾钩、情绪峰值、天数推进、新修为/新世界观信息、影响剧情的关键台词，追加或更新对应行；语雀/both 模式两处都更新。历史教训：7 个空分组空了两百多章，建库时建了但回写流程没要求填。
    - **更新 Mermaid 关系图**（写章节后必做，规则见下方「更新图」命令）：地点图——每个地点一个节点，角色在两地间移动过则连线、线上标角色名；新增地点/角色移动时自动刷新关系图 DOC（2026-10-09 修正：此前「默认自动更新」未落入流程步骤导致写章后从不生成）
    - **本地备份快照**（`backup.mode=local` 时）：跑 `node scripts/backup-snapshot.js <config.json> <章节号>`，把 状态快照 + 本章正文 + chXXX-changes 快照到 `backup.local_path/<时间戳>-chXXX/`（加 `--full` 全量备份 正文/ + 设定/）；非 local 模式自动跳过、退出码 0；失败不阻断（2026-10-10 补实现，此前是空承诺）
19. **冲突检测**：状态回写后跑 `node scripts/check-conflicts.js <状态快照.md> <设定目录>`——快照内部确定性冲突：角色重复登记 / 已死角色未标死 / 物品双持有 / 时间线倒流（另位置留空给提示）；**含档案完整性对账**：快照角色/物品表 vs 设定目录档案文件，缺档列提示（龙套合法无档可忽略，重要角色需补档——2026-10-12 实弹：曾缺 30+ 份档案，靠这招兜底）；自由文本 / 跨章区间位置冲突归 AI 侧；有冲突则提示

22. 更新配置追踪字段：
    - **2026-10-12 P2-7 落地：回写配置一条命令**——`node scripts/finalize-config.js <config.json> <小说目录> [--chapter N] [--sweet-spot 类型] [--hook-start 类型,强度] [--hook-end 类型,强度] [--emotion 情绪,强度]`：自动算 `current_chapter`（最大章号）/`written_chapters`（全部章号）/`total_words`（全量重算，口径统一），LLM 判断字段（爽点/钩子/情绪峰值）显式传参，4 个 consecutive_* 自动重置；其余字段不动。`--chapter` 必须为正整数且 **≥ 目录最大章号**（传小会报错拦下，防 current_chapter 写回退）；每个 flag 缺值直接报用法错误，不静默默认
    - **语雀档案批量同步（both 模式，P2-7 落地）**：`node scripts/yuque-doc.js sync --book <id> --local <小说目录> [--dry-run] [--only <关键字>]` 一键把本地 设定/ 推语雀（不含 `设定/changes/`——changes 以语雀为权威；标题头/尾部换行差异自动豁免）；先 `--dry-run` 预演确认差异方向（本地新才推，若语雀新需反向处理），再真跑。远端若是 `lake` 格式（在语雀编辑器里写过）会拒写，免得推 markdown 冲掉排版；某一篇失败不影响其余，跑完逐条列出并以 exit 1 收尾（详见手册 7.2）
    - **语雀反向拉取（语雀改过、本地还是旧的）**：`node scripts/yuque-doc.js pull --book <id> --local <小说目录> [--write] [--only <关键字>]` 把语雀上的设定档拉回本地。默认只列清单，`--write` 才落盘；覆盖前把本地旧版存 `设定/.sync-backup/<时间戳>/`，要还原拷回去即可。**正文永远不参与**——语雀正文是剥过 CHANGES 的上传版，拉回来会抹掉本地完整版；远端 `lake` 格式或空正文跳过。`sync`/`pull` 会在小说根记 `.yuque-sync-state.json` 基线（每篇的本地/远端指纹），有它才分得清谁改的：只有本地改过的档 pull 不动、提示去 sync；两边都改过则跳过并 exit 1，确认以语雀为准加 `--force`；单篇失败不中断、跑完 exit 1 汇总（详见手册 7.2.1）
