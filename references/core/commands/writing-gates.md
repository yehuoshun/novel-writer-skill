# 命令详解：写作相关 · 12 门禁与交付前检查

> 何时加载：正文与 CHANGES 写完、进入阶段三时。[writing.md](writing.md) 只留阶段骨架与门禁清单，逐条判据、收尾、交付前检查都在这里。

## 阶段三：12 门禁校验

> **12 门禁 ↔ 阶段三条目号映射**（两套编号并存易混淆，统一以条目号引用）：
> | 12 门禁 | 阶段三条目 | 内容 |
> |---|---|---|
> | Gate 1-6（写作质量 6 门禁） | 条目 10 | 文本健康 / AI句式 / 心理外化 / 节奏 / 对话 / 结尾（子项见 [references/quality/anti-ai-gates.md](../../quality/anti-ai-gates.md)） |
> | 引用校验 | 条目 11 | CHANGES 声明实体须已建档 |
> | 一致性校验 | 条目 12 | 移动/已死/地点状态/物品归属 vs 快照 |
> | 描写一致性 | 条目 13 | 正文外貌描写 vs 快照/档案 |
> | 未知实体检测 | 条目 14 | 正文冒头未声明（容错≤5，仅警告） |
> | 蓝图出场合规 | 条目 15 | 细纲蓝图必出场实体 |
> | 伏笔闭环 | 条目 16 | 伏笔状态机一致性 |
> 注：文档内「门禁 N」统一指**阶段三条目号**（如「门禁 14」= 未知实体，见条目 14）；勿按 12 门禁序数换算（按序数数蓝图是第 11 个、伏笔是第 12 个，会与「门禁 11=引用校验」冲突）。
> ⚠️ **顺序铁律**：一致性 / 描写一致性 / 伏笔闭环 / 蓝图校验必须基于**上一章快照**、在**状态回写（阶段四）之前**执行——回写后快照已是本章目标态，再校验会误报。本地模式跑 `node scripts/check-consistency.js <状态快照.md> <本章.md> <设定目录> [细纲.md]` 自动查「引用 / 一致性 / 描写一致性 / 伏笔闭环 / 蓝图出场合规 / 未知实体候选 / 交接包必填」（对应条目 11/12/13/15/16/14；交接包必填为协议兜底，缺失打回）。蓝图校验另有警告：细纲存在但蓝图清单无本章行（文档要求每章附蓝图）、必出场角色仅出场 1 次（叙事力度）、无法从文件名解析章号（跳过校验，不再静默）；未知实体候选仅警告不阻断。
> 📌 **语雀模式跑脚本**：脚本按文件路径工作，语雀模式须先把本章正文、上一章快照、涉及设定档导出到临时目录再跑（临时目录法见 [references/integrations/yuque-integration.md](../../integrations/yuque-integration.md) 6.1）。
> ⚠️ **工具操作坑**：① `mcporter` 必须在 **workspace 目录**（`config/mcporter.json` 所在）执行，在别的 cwd 调用会报「Unknown MCP server」（`mcporter list` 却仍能列出——别被迷惑）；② `scan-text-health.js` 用 `文件路径 [config.json]` 作**参数**，**别用 `< 重定向 + config`**（会把 config 当正文读，假报「字数不足」）。

10. **写作质量门禁**（6 Gate，全名见 [references/quality/anti-ai-gates.md](../../quality/anti-ai-gates.md)：Gate 1 文本健康 / Gate 2 AI句式 / Gate 3 心理外化 / Gate 4 节奏 / Gate 5 对话 / Gate 6 结尾）；本地模式跑 `node scripts/scan-text-health.js < 正文文件.md [config.json]` 自检 Gate 1（词无定性，分布是判据；**传 config.json 时对照 `writing.chapter_words` 做字数门禁：正文汉字数 < min → 硬伤打回，> max → 提示**），Gate 2–6 的**可规则化子集**跑 `node scripts/scan-ai-tells.js <正文.md>`（序数/总结/时代套话、心理外化成簇、段落等厚、对话占比/连发、章尾钩子信号——**仅提示不判硬伤**，语义判断仍归 AI；其中 Gate6「章尾钩子信号」为**启发式**，误报以 AI/复核终判、不必为误报改文）。下列为 Gate 1 检测维度：破折号统计（`——` 计数，**>3 判硬伤打回**且附上下文，≤3 时列出上下文供人工核对是否全为对话打断）
    - **断句检测**：逗号链（单句 ≥6 逗号警告）、句长分布（25 字+ 占比、≤8 字碎片）
    - **语句通顺检测**：口语虚词密度（净句警告）、同主语连发（连续 3+ 句同一开头）、连接词滥用（然后/接着/于是）、「是…的」书面判断腔、填充词
    - **修饰分布**：比喻密度、「只有/仅仅/恰好」封闭逻辑词（优先「还有/又」开放叙述）
    - **认知句模式**：他总觉得/这让他知道/他意识到/久到/忽然（允许 1 处，成簇替换）
    - **标点硬伤**：半角标点混入、引号不成对（❌ 必须改；HTML 注释里的 `!` 是注释语法，豁免）
    被门禁打回需重写/润色时，加载 [references/quality/anti-ai-polish.md](../../quality/anti-ai-polish.md)（可编辑范围分级+信息账本+修补顺序+CHANGES 块保护+三遍法+改写范例）
11. **引用校验**（新增）：CHANGES 中**5 类声明段**（角色状态变化/角色移动/物品流转/地点状态变化/势力状态变化）出现的角色/地点/物品/势力 ID 是否在设定中存在（本地可跑 `check-consistency.js`）
    - 引用不存在的 ID → 打回，标注"未登记实体：XXX"
    - **零容忍**：凡是声明段声明的实体一律须已登记；新实体**先走建档流程再写章**（走「角色首次登场流程」/新建地点物品文档），不允许"先写后补"
    - **新剧情节点段的「涉及角色」仅作剧情索引**，不按零容忍处理；**只写已建档实体，无名龙套不入 CHANGES**（第22章误写「探路队探子（无名龙套）」被脚本打回）；无档案实体出现在摘要时脚本给出警告（不阻断）提示补档或改走声明段，正文新实体由门禁 14 兜底
12. **一致性校验**（新增）：CHANGES 的声明是否与事实快照矛盾（本地可跑 `check-consistency.js`；须基于上一章快照、回写前执行）
    - 例：快照中张三在烈焰谷，CHANGES 声明张三从天剑宗出发 → 矛盾
    - 例：快照中李四已死亡，CHANGES 声明李四状态变化 → 矛盾
    - 脚本自动查 4 类：角色移动出发地 vs 快照当前位置、已死角色登场、**地点状态变化出发态 vs 快照地点状态表**、**物品流转原持有者 vs 快照物品归属表**（后两类与角色移动同构）
13. **描写一致性校验**（新增）：正文中角色外貌描写是否与状态快照「角色外貌」表 / 角色档案矛盾（本地可跑 `check-consistency.js`；优先取快照外貌表，无则回退档案——旧格式「发色/瞳色」标签或「外貌描述」自由文本提取；发/瞳颜色支持「色/白+的+发」变体如「银色的头发」「银白的长发」，双色词按主色归一化避免误拦；自动排除非固有色短语——眼部部件/俗语（黑眼圈/白眼/眼眶红/眼白）与头发配件（黄发卡/红发带/发夹）及临时泛红（通红的眼睛），正文侧与档案/快照取值侧共用同一判定，v3.3.54 起）
    - 加载本章出场角色的档案（发色、瞳色、外貌特征、性格标签）
    - 正文中写"张三的金色长发"但档案写黑发 → 打回
    - 正文中地点描写与地点特征档案矛盾（如档案写「终年云雾缭绕」、正文写「寸草不生」）→ **AI 侧人工判断打回**：自由文本特征语义无法规则可靠判定，脚本只管可枚举维度（角色外貌 / 地点状态 / 物品归属，见门禁 12）
14. **未知实体检测**（新增）：**正文里出现、但 CHANGES 未声明**的未登记角色/地点/势力是否超阈值
    - 与门禁 11 分工：CHANGES 已声明的走门禁 11（零容忍）；本门禁只管「正文冒出来、CHANGES 漏声明」的那部分，给它 ≤5 的容错
    - 阈值：一章 ≤ 5 个新实体（区分有剧情作用的 vs 龙套）
    - 龙套（店小二、路人甲，出场 < 2 句且无姓名）不计入
    - 超阈值 → 打回，标注"新增实体过多：XXX"
    - 本地可跑 `check-consistency.js`（随写章一起）输出「未知实体候选」清单——零依赖启发式（地点/势力后缀词 + 常见姓氏两字名，正文出现 ≥2 次才记，减去已登记/已声明的）；**脚本仅给候选警告，打回与否由 AI 依清单终判**（切词必有噪声，硬拦风险大于收益）
15. **蓝图出场合规**（新增）：细纲/蓝图指定的角色/势力/地点是否在正文中实际出现（蓝图出场清单格式见 [references/outline/outline-arrangement.md](../../outline/outline-arrangement.md)「蓝图出场清单」；本地可跑 `check-consistency.js <快照> <本章> <设定目录> <细纲.md>` 自动查）
    - 蓝图列出张三、李四、王五 → 正文只写了张三 → 缺额 > 阈值 → 打回
    - 视角角色仅出现 1 次 → 警告「叙事力度不足」（本地脚本已实现同款警告）
    - ⚠️ 蓝图表校验依赖章节文件名含「第N章」（约定 `第NNN章.md`）；文件名不符时脚本给警告并跳过本章蓝图表校验（v3.3.55 起不再静默）
    - **蓝图缺失/口径**：细纲存在但蓝图清单无本章行 → 先补该行再写（脚本给警告）；蓝图实体名须与正文出现**口径一致**——本章刻意不点名的势力（悬疑设计），蓝图「必出场势力」填「无」或与正文一致的表述，勿写设定标签词，否则校验失败
16. **伏笔闭环校验**（新增）：伏笔动作与伏笔状态机的一致性（本地可跑 `check-consistency.js` 兜底：引用登记 / 状态回退 / 已死角色 / 埋设 10 章未推进警告）
    - ✅回收未写明「回收方式」→ 警告（无法核对回收是否匹配埋设时的预期读者效果，v3.3.55 起脚本兜底）
    - 🔨埋设：创建新伏笔 → 必须分配唯一伏笔ID（vX），写清类型+预期读者效果，加入伏笔状态表
    - ➡️推进 / ✅回收 / ❌废弃：引用的伏笔ID 必须已在伏笔状态表中（未登记 → 打回，标注「未登记伏笔：vX」）
    - ✅回收的伏笔必须与埋设时的预期读者效果一致（回收方式和预期对不上 → 打回）
    - 状态迁移只能沿 已埋设→已推进→已回收/已废弃 方向；从已回收/已废弃回退 → 打回
    - 正文出现「像伏笔」的线索但 CHANGES 未声明且总览无此伏笔 → 打回，标注「疑似未登记伏笔，请补充设计或删除线索」
    - 伏笔埋设后 10 章未推进且未回收 → 警告「伏笔 vX 已埋设 N 章未推进」
    - 检测到旧格式伏笔（无 vX ID，如「优先级：核心/普通/彩蛋」写法）→ 警告「建议迁移到 vX 格式」，不打回
    - **双写一致性**：同一件事实有两份记录——`伏笔追踪/vID-*.md` 里的 `- 状态：` 和快照「## 伏笔状态」表的状态列。两处不一致 → 打回（`[伏笔双写] vX 档案状态「已埋设」与快照「已推进」不一致`）；只在一边登记（有档案没表行、有表行没档案）→ 警告。用 `apply-changes.js` 回写快照时两处自动一起改；手改的话两处一起改。档案里没写 `- 状态：` 的不比对。

**阶段三收尾（强制）**：产出结构化「门禁结果」报告（12 门禁逐项带结论，格式见下方「门禁结果输出格式」），并跑 `node scripts/verify-gate-report.js <门禁报告.md> --data <数据报告.json>` 校验**完整性 + 结论口径**——缺项或与数据报告不符 → 补齐/改正后重跑，**禁止一句「门禁通过」蒙混**。结论口径：**以 `scripts/gate-report.js` 产出的数据报告为准**，文本报告只负责可读化。
> 完整性过后，**再走双模型独立复核**（能不人工就不人工，见下方「验收分级」）：换新上下文/另一模型独立跑同一章门禁，产第二份报告，跑 `node scripts/compare-gate-reports.js <主报告> <复核报告>`——**完全一致 → 自动通过，无需人工**；**报告缺项 → 重跑复核（非人工）**；**两模型结论分歧（歧义）→ 升级人工**（人工只裁歧义，不是每章都审）。这样 AI 侧判断的可靠性不再靠单模型自觉，也无需每章都找人。
> ⚠️ **compare 报告格式铁律（两次假分歧后固化）**：两份报告必须同格式——① Gate 拆逐条（`**Gate 1 文本健康 ✅**`…`**Gate 6 结尾 ✅**`），不合并成「Gate1-6」一行；② 门禁项判定行同款（`**引用校验 ✅**`/`**一致性校验 ✅**`…），判定行不带 ⚠️；③ **脚本三件套表格行避开「一致性/未知实体/引用/蓝图/伏笔」等门禁关键词**——compare 脚本按 `find()` 取第一处匹配行，表格行带这些词会抢判定（表格行写「未知实体候选警告」→ 主报告被误判 warn）。两份同格式后重跑即一致。
> ⚠️ **修复后必须二次复核（硬规则）**：复核发现问题 → 修复正文/CHANGES 后，**必须让复核模型重看修正版**（验证修复到位 + 无新问题，产出二次复核结论附于主报告），**未二次复核不得判通过、不得进入阶段四同步**。拿旧复核报告对比修正版 = 自欺（踩过两次：拿旧复核报告对比修正版）。二次复核仍发现问题 → 再修再核，直至通过。
> ⚠️ **复核结论写入时机**：主报告先写「二次复核：待复核模型重看修正版」占位；**复核模型产出结论后才落笔**，结论只能由复核结果驱动（通过/未通过+发现项），禁止主审提前自写「复核确认通过」——复核前的结论段撤稿返工

**交付前检查（强制）**：正文生成完成、上传前**必做**，与门禁脚本同级，产出「交付前检查」结论（过/不过 + 修了什么），不过则修完重跑门禁再交付。两类：
- **上下文连贯**：① 台词事实回溯——每句台词引用的动作/事件必须正文有对应描写（规则与高发场景见 [references/quality/anti-ai-gates.md](../../quality/anti-ai-gates.md)「台词事实回溯」节）；② 前后文衔接——指代（这个/他/那东西的指向）、时序（先发生的事不能后写）、因果（台词感谢的事必须先有事实）逐段核对；③ **时间账本核对**——本章「第几天/第N天」与快照「当前时间」一致，章内不得出现两个相同天数（案例：同一「第三天」跑出两套时间线）；④ **断句拆分有理由**——叙述句默认合并，「一句话能写完偏拆几段」= 红线，段落拆分必须有理由（冲击点/视角切换/对话），如「元婴。」「金丹。」独词段、「一行一停」；**分两级查**：段落级（独词段/短行）+ 句内级（同语义团被句号切开——能逗号连就逗号连，章尾句号密度重点查）；**章尾抒情专项**：章尾只留一个钩子，独白/拟人/隐喻密度降到最低；⑤ **物品去向闭环**——本章内某物品脱离原持有者（掉落/遗失/被夺/移交），必须写清去向（捡回/转移/声明丢失）并进 CHANGES 物品流转；随身兵器/关键道具首进声明段前先建档（脚本与双模型复核都抓不到，只能主审自查）；⑥ **方位一致性**——正文提到的地点相对方位/距离必须与「地理方位」表一致，不得与已锁定方位矛盾（语义方位脚本查不了，归 AI/复核人工核对）
- **AI 味密度**：① 数金句（带俏皮/对仗/格言味、可独立成句被记住的句子）≤2；② 数同类句式成簇（有人…有人…/想起X想起Y/说…的… 同章 ≥2 处即违规）≤1；③ 探子/转述台词信息点 ≥3 必须已拆轮；④ 章尾妙笔（意象收尾/对仗钩）已改朴素；⑤ 对仗句（A；B 对称）已拆；⑥ 精确数字未成簇（布局/距离/时长枚举式 ≥3 处即模糊化）；⑦ 章尾无宣言句（X会知道/究竟是什么式已改口语）；⑧ 顺滑编排插桩（对话轮转插停顿/动作链插迟钝/群体反应延迟化/章尾意象改动作）——详见 [references/quality/anti-ai-gates.md](../../quality/anti-ai-gates.md)「顺滑编排型指纹」
- **结构指纹·讲解章**：动笔前先判章节类型——动作/场景章天然安全；**问答/讲古/汇报型纯对话章天然高危**，须按 [references/quality/anti-ai-gates.md](../../quality/anti-ai-gates.md)「结构指纹·讲解章」自查（对话段占比 >50% / 段均字 <30 / 「>60字」段 <5% 命中 ≥3 即高危）并主动「对话并段 + 长段承载叙述 + 长短夹杂」。**注意：脚本门禁与双模型复核都抓不到本指纹，三者全绿 ≠ 外部检测器过**，不得拿「门禁全绿」当交付依据
- **语句检查**：叙述层通顺（口语杂质只进对话层：「不知道什么时候落的」→「落下的」）、病句/错别字/漏字、标点
- 交付 = 章节给老板验收/发布；**检查必须在回写前完成**，改完正文再上传（避免回写后又改正文造成快照/存储不一致）

**门禁结果输出格式**：
```
🛡️ 门禁结果（第X章）
  ✅ Gate 1-6 写作质量：通过（文本健康✓ / AI句式1处已修正）
  ✅ 引用校验：通过（CHANGES 引用 5 个实体，均在设定中）
  ✅ 一致性校验：通过
  ✅ 描写一致性：通过
  ✅ 未知实体检测：通过（新增 2 个：路人甲-龙套不计入，黑风寨-已登记）
  ✅ 蓝图出场合规：通过（指定 3 人出场，实际 3 人）
  ✅ 伏笔闭环校验：通过（埋设 v3 / 推进 v1 / 未登记 0）
  📋 交接包已更新（供第 X+1 章使用）
```
（Gate 1–6 可合并一行「Gate 1-6 写作质量」，也可逐条 Gate 1…Gate 6；6 专项逐条必列。此报告存为文件后跑 `node scripts/verify-gate-report.js <报告.md> --data 设定/changes/chNNN-gate-report.json`：先校验完整性（缺项打回），再逐项比对结论口径——文本写 ✅ 而数据报告是 warn/fail 同样打回。）
> ⚠️ **结论来源**：这份文本报告的每行结论都是**抄**数据报告的，不是重新判一遍——先跑 `node scripts/gate-report.js … --out 设定/changes/chNNN-gate-report.json`，再按它的 gates 逐项写；数据报告里是 warn 就写 ⚠️，是 skip 就写「跳过（不适用）」。凭印象写 ✅ 属于伪造验收记录。
> ⚠️ **报告格式硬要求（verify-gate-report.js 逐行匹配）**：每行标题必须**自带 ✅/⚠️/❌ 结论词**（如「- Gate 1-6 写作质量 ✅ 通过（…）」），结论放在标题下一行会被判「缺结论」打回；表头必须含「门禁结果」字样（结论分行写法会被打回）

**验收分级（能不人工就不人工）**：
- **自动验收**（默认，无需人工）：① 脚本门禁：一致性 / 冲突 / 文本健康 / AI味 / 门禁报告完整性；② 单测 + 三个集成回归（CI 绿即过）；③ **AI 判层 → 双模型独立复核**：新上下文/另一模型独立跑同一章门禁，两份报告经 `compare-gate-reports.js` 比对——**完全一致即自动通过**（把 AI 判的正确性也自动化，不再靠单模型自觉）；④ **复核发现问题 → 修复后二次复核修正版**（硬规则）：验证修复到位+无新问题后方可判通过/同步，未二次复核不得放行。
- **人工验收（最后兜底）**：**仅当两模型报告出现结论分歧（= 歧义）**时升级人工——人工只裁定歧义，不是每章都审。报告缺项/不完整 = 流程问题 → **重跑复核**，不找人。
