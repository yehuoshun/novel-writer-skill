# 命令详解：写作相关

> 何时加载：写章节 / 续写 / 回溯时（每次动笔前）。SKILL.md「命令列表」只留一句话，这里是完整流程与判据。


## 写章节
```
写章节 [章节号]
写章节 [章节标题]
写章节          # 不指定时，默认写最新章节（info.current_chapter + 1）
```
**流程**：

**阶段一：准备**
1. 校验配置文件有效性
2. 定位续写位置 + 读交接包：先跑 `node scripts/next-chapter.js <config.json>`——它把「已发布到第几章（账本）/ 正文目录到第几章 / 下一章该写第几号 / 交接包内容 / 快照有没有欠账」一次列出来，出现 `⛔` 先处理（多为上一章 CHANGES 没回写快照，发布会被 exit 4 拦住）再动笔；同一份输出里还有**伏笔账**（`## 伏笔状态` 每条未了结伏笔离「该推进」还剩几章：长线 5 章起提醒 / 10 章逾期，短线·误导 2/4，彩蛋 3/6；🔴 逾期、🟡 快到线，已回收的不算）——动笔前先看它，能顺手推一条就写进本章细纲，别等门禁在写完后再喊；再读 `状态快照.md` 顶部的 `## 下章交接包`（上一章留下的交接单）与快照正文确认当前所有实体状态（不读历史）
3. 按需加载相关设定（本章涉及的角色/地点/物品的详细档案；**涉及多地相对位置时加载「地理方位」表**核对，2026-10-12 补）
4. 参考本章细纲（含蓝图出场清单），必要时加载 [references/outline/outline-arrangement.md](../../outline/outline-arrangement.md) 和 [references/outline/expectation-techniques.md](../../outline/expectation-techniques.md)
   - ⚠️ **细纲缺失禁止开写**：设定中无细纲文档（本地：`设定/大纲/细纲/` 无文件；语雀：`大纲/细纲` 分组无 DOC）时，先执行「写大纲」生成全书大纲+细纲（含蓝图出场清单），再回来写章节——不允许跳过大纲直接开写
   - **校对本草对白体例（2026-10-12 补）**：先读本书近 1-2 章正文，确认对白写法（如本书=「说，…」无引号体，「」仅用于引述片段；或引号体），照本书体例写——勿套用通用引号体（实弹：第22章误用「」引号体，全章改写）
   - **细纲/蓝图缺本章行（2026-10-12 补）**：细纲存在但蓝图清单无本章行 → **先补该行**（含必出场角色/势力/地点 + 戏分）再写；蓝图「必出场势力」若本章悬疑设计刻意不点名，填「无」或与正文一致的表述，勿写设定标签词（实弹：第22章蓝图要求「外部势力」出场但正文刻意不点名 → 校验失败）
5. 生成这章大纲（标注：核心事件、本章爽点类型、章首钩子类型、章尾悬念 + **每个核心事件的场景字数配额**，Σ 落在 `writing.chapter_words` 目标区间、一般 2800-3400）
   - **字数配额脚手架（2026-10-12 补）**：配额是防「骨架化欠量」的**下限脚手架**，不是硬卡（硬卡会逼出注水）；允许 ±15% 浮动，超上限也提示
6. 发给你确认
7. 你确认/修改

**阶段二：写作 + 变更声明**
8. 写正文（**动笔前先对阶段一的场景字数配额；全章写完先跑 `scan-text-health` 字数门禁，欠量按缺口场景补（对话轮次/厚段/细节），禁整篇注水**——2026-10-12 第22章实弹：初稿骨架化只 1769 字，挂脚本才发现；实时字数提醒：3500字提醒进度，4000字提醒上限，不低于2500字；排版规范：全角标点“ ”、段首缩进两全角空格、不用半角标点、**叙述层破折号≤3处且仅限对话打断（规则见 [references/quality/anti-ai-gates.md](../../quality/anti-ai-gates.md)「破折号限额」）**、**精确数字不枚举成簇（≥3处即模糊化）**、**对仗陈述句不≥2处**、**章尾不用宣言句**（规则见 [references/quality/anti-ai-gates.md](../../quality/anti-ai-gates.md)「金句密度限额/精确数字成簇/工整对仗句」），见 [references/quality/anti-ai-gates.md](../../quality/anti-ai-gates.md) Gate 5；**2026-10-12 P0 落地：写完立刻自查破折号与字数——`node scripts/scan-text-health.js <本章.md> <config>` 一条命令同时出字数（低于下限打回）与破折号计数（超 3 打回），欠量/超限当场补，别等门禁阶段**）
   - 参考 [references/style/style-modules.md](../../style/style-modules.md) 确保文风一致
   - 参考 [references/hook/hook-techniques.md](../../hook/hook-techniques.md) 确保钩子到位
9. **AI 必须在正文后输出 `---CHANGES---` 变更声明块**（见下方「CHANGES 变更声明协议」；**2026-10-12 P0 落地：CHANGES 块从正文实际改动提取、对照正文逐条核对（角色状态/移动、物品流转、地点/势力状态、伏笔推进、交接包），不凭记忆手写**——第23章实弹：手写 CHANGES 里陈长老引文与正文漂移，门禁阶段才发现）
   - ⚠️ **CHANGES 块行首必须顶格**：正文自然段首行缩进两全角空格是排版要求，但 `---CHANGES---`、`---END CHANGES---` 及块内**每一行都不能带全角空格缩进**——parse-changes.js 按行首精确匹配，一旦缩进即报「No CHANGES block found」打回（2026-10-10 实弹暴露）

**阶段三：12 门禁校验**（全部自动，不通过则打回 AI 重写）
> **12 门禁 ↔ 阶段三条目号映射**（两套编号并存易混淆，统一以条目号引用）：
> | 12 门禁 | 阶段三条目 | 内容 |
> |---|---|---|
> | Gate 1-6（写作质量 6 门禁） | 条目 10 | 文本健康 / AI句式 / 心理外化 / 节奏 / 对话 / 结尾（子项见 [references/quality/anti-ai-gates.md](../../quality/anti-ai-gates.md)） |
> | 引用校验 | 条目 11 | CHANGES 声明实体须已建档 |
> | 一致性校验 | 条目 12 | 移动/已死/地点状态/物品归属 vs 快照 |
> | 描写一致性 | 条目 13 | 正文外貌描写 vs 快照/档案 |
> | 未知实体检测 | 条目 14 | 正文冒头未声明（容错≤5，仅警告） |
> | 蓝图出场合规 | 条目 15 | 细纲蓝图必出场实体 |
> | 伏笔闭环 | 条目 16 | 伏笔状态机一致性 |
> 注：文档内「门禁 N」统一指**阶段三条目号**（如「门禁 14」= 未知实体，见条目 14）；勿按 12 门禁序数换算（按序数数蓝图是第 11 个、伏笔是第 12 个，会与「门禁 11=引用校验」冲突）。
> ⚠️ **顺序铁律**：一致性 / 描写一致性 / 伏笔闭环 / 蓝图校验必须基于**上一章快照**、在**状态回写（阶段四）之前**执行——回写后快照已是本章目标态，再校验会误报。本地模式跑 `node scripts/check-consistency.js <状态快照.md> <本章.md> <设定目录> [细纲.md]` 自动查「引用 / 一致性 / 描写一致性 / 伏笔闭环 / 蓝图出场合规 / 未知实体候选 / 交接包必填」（对应条目 11/12/13/15/16/14；交接包必填为协议兜底，缺失打回）。蓝图校验另有警告：细纲存在但蓝图清单无本章行（文档要求每章附蓝图）、必出场角色仅出场 1 次（叙事力度）、无法从文件名解析章号（跳过校验，不再静默）；未知实体候选仅警告不阻断。
> 📌 **语雀模式跑脚本**：脚本按文件路径工作，语雀模式须先把本章正文、上一章快照、涉及设定档导出到临时目录再跑（临时目录法见 [references/integrations/yuque-integration.md](../../integrations/yuque-integration.md) 6.1）。
> ⚠️ **工具操作坑（2026-10-12 补）**：① `mcporter` 必须在 **workspace 目录**（`config/mcporter.json` 所在）执行，在别的 cwd 调用会报「Unknown MCP server」（`mcporter list` 却仍能列出——别被迷惑）；② `scan-text-health.js` 用 `文件路径 [config.json]` 作**参数**，**别用 `< 重定向 + config`**（会把 config 当正文读，假报「字数不足」）。
10. **写作质量门禁**（6 Gate，全名见 [references/quality/anti-ai-gates.md](../../quality/anti-ai-gates.md)：Gate 1 文本健康 / Gate 2 AI句式 / Gate 3 心理外化 / Gate 4 节奏 / Gate 5 对话 / Gate 6 结尾）；本地模式跑 `node scripts/scan-text-health.js < 正文文件.md [config.json]` 自检 Gate 1（词无定性，分布是判据；**传 config.json 时对照 `writing.chapter_words` 做字数门禁：正文汉字数 < min → 硬伤打回，> max → 提示**——此前字数约束只靠写作时自觉，2026-10-10 实弹暴露后补脚本兑底），Gate 2–6 的**可规则化子集**跑 `node scripts/scan-ai-tells.js <正文.md>`（序数/总结/时代套话、心理外化成簇、段落等厚、对话占比/连发、章尾钩子信号——**仅提示不判硬伤**，语义判断仍归 AI；其中 Gate6「章尾钩子信号」为**启发式**，误报以 AI/复核终判、不必为误报改文——2026-10-12 第22章实弹：危机钩齐全仍报「疑似无钩子」）。下列为 Gate 1 检测维度：破折号统计（`——` 计数，**>3 判硬伤打回**且附上下文，≤3 时列出上下文供人工核对是否全为对话打断——2026-10-12 第23章实弹：此前靠复核第一轮人工数才抓出 5 处超限，主报告还数漏，现脚本直接兑底）
    - **断句检测**：逗号链（单句 ≥6 逗号警告）、句长分布（25 字+ 占比、≤8 字碎片）
    - **语句通顺检测**：口语虚词密度（净句警告）、同主语连发（连续 3+ 句同一开头）、连接词滥用（然后/接着/于是）、「是…的」书面判断腔、填充词
    - **修饰分布**：比喻密度、「只有/仅仅/恰好」封闭逻辑词（优先「还有/又」开放叙述）
    - **认知句模式**：他总觉得/这让他知道/他意识到/久到/忽然（允许 1 处，成簇替换）
    - **标点硬伤**：半角标点混入、引号不成对（❌ 必须改；HTML 注释里的 `!` 是注释语法，豁免）
    被门禁打回需重写/润色时，加载 [references/quality/anti-ai-polish.md](../../quality/anti-ai-polish.md)（可编辑范围分级+信息账本+修补顺序+CHANGES 块保护+三遍法+改写范例）
11. **引用校验**（新增）：CHANGES 中**5 类声明段**（角色状态变化/角色移动/物品流转/地点状态变化/势力状态变化）出现的角色/地点/物品/势力 ID 是否在设定中存在（本地可跑 `check-consistency.js`）
    - 引用不存在的 ID → 打回，标注"未登记实体：XXX"
    - **零容忍**：凡是声明段声明的实体一律须已登记；新实体**先走建档流程再写章**（走「角色首次登场流程」/新建地点物品文档），不允许"先写后补"
    - **新剧情节点段的「涉及角色」仅作剧情索引**，不按零容忍处理；**只写已建档实体，无名龙套不入 CHANGES**（实弹：第22章新剧情节点误写「探路队探子（无名龙套）」被脚本打回）；无档案实体出现在摘要时脚本给出警告（不阻断）提示补档或改走声明段，正文新实体由门禁 14 兜底
12. **一致性校验**（新增）：CHANGES 的声明是否与事实快照矛盾（本地可跑 `check-consistency.js`；须基于上一章快照、回写前执行）
    - 例：快照中张三在烈焰谷，CHANGES 声明张三从天剑宗出发 → 矛盾
    - 例：快照中李四已死亡，CHANGES 声明李四状态变化 → 矛盾
    - 脚本自动查 4 类：角色移动出发地 vs 快照当前位置、已死角色登场、**地点状态变化出发态 vs 快照地点状态表**、**物品流转原持有者 vs 快照物品归属表**（后两类 v3.3.40 起，与角色移动同构）
13. **描写一致性校验**（新增）：正文中角色外貌描写是否与状态快照「角色外貌」表 / 角色档案矛盾（本地可跑 `check-consistency.js`；优先取快照外貌表，无则回退档案——旧格式「发色/瞳色」标签或「外貌描述」自由文本提取；发/瞳颜色支持「色/白+的+发」变体如「银色的头发」「银白的长发」，双色词按主色归一化避免误拦；自动排除非固有色短语——眼部部件/俗语（黑眼圈/白眼/眼眶红/眼白）与头发配件（黄发卡/红发带/发夹）及临时泛红（通红的眼睛），正文侧与档案/快照取值侧共用同一判定，v3.3.54 起）
    - 加载本章出场角色的档案（发色、瞳色、外貌特征、性格标签）
    - 正文中写"张三的金色长发"但档案写黑发 → 打回
    - 正文中地点描写与地点特征档案矛盾（如档案写「终年云雾缭绕」、正文写「寸草不生」）→ **AI 侧人工判断打回**：自由文本特征语义无法规则可靠判定，脚本只管可枚举维度（角色外貌 / 地点状态 / 物品归属，见门禁 12）
14. **未知实体检测**（新增）：**正文里出现、但 CHANGES 未声明**的未登记角色/地点/势力是否超阈值
    - 与门禁 11 分工：CHANGES 已声明的走门禁 11（零容忍）；本门禁只管「正文冒出来、CHANGES 漏声明」的那部分，给它 ≤5 的容错
    - 阈值：一章 ≤ 5 个新实体（区分有剧情作用的 vs 龙套）
    - 龙套（店小二、路人甲，出场 < 2 句且无姓名）不计入
    - 超阈值 → 打回，标注"新增实体过多：XXX"
    - 本地可跑 `check-consistency.js`（随写章一起）输出「未知实体候选」清单——零依赖启发式（地点/势力后缀词 + 常见姓氏两字名，正文出现 ≥2 次才记，减去已登记/已声明的）；**脚本仅给候选警告，打回与否由 AI 依清单终判**（切词必有噪声，硬拦风险大于收益）
15. **蓝图出场合规**（新增）：细纲/蓝图指定的角色/势力/地点是否在正文中实际出现（蓝图出场清单格式见 [references/outline/outline-arrangement.md](../../outline/outline-arrangement.md)「蓝图出场清单」；本地可跑 `check-consistency.js <快照> <本章> <设定目录> <细纲.md>` 自动查）
    - 蓝图列出张三、李四、王五 → 正文只写了张三 → 缺额 > 阈值 → 打回
    - 视角角色仅出现 1 次 → 警告「叙事力度不足」（本地脚本已实现同款警告）
    - ⚠️ 蓝图表校验依赖章节文件名含「第N章」（约定 `第NNN章.md`）；文件名不符时脚本给警告并跳过本章蓝图表校验（v3.3.55 起不再静默）
    - **蓝图缺失/口径（2026-10-12 补）**：细纲存在但蓝图清单无本章行 → 先补该行再写（脚本给警告）；蓝图实体名须与正文出现**口径一致**——本章刻意不点名的势力（悬疑设计），蓝图「必出场势力」填「无」或与正文一致的表述，勿写设定标签词，否则校验失败（实弹：第22章「外部势力」）
16. **伏笔闭环校验**（新增）：伏笔动作与伏笔状态机的一致性（本地可跑 `check-consistency.js` 兜底：引用登记 / 状态回退 / 已死角色 / 埋设 10 章未推进警告）
    - ✅回收未写明「回收方式」→ 警告（无法核对回收是否匹配埋设时的预期读者效果，v3.3.55 起脚本兜底）
    - 🔨埋设：创建新伏笔 → 必须分配唯一伏笔ID（vX），写清类型+预期读者效果，加入伏笔状态表
    - ➡️推进 / ✅回收 / ❌废弃：引用的伏笔ID 必须已在伏笔状态表中（未登记 → 打回，标注「未登记伏笔：vX」）
    - ✅回收的伏笔必须与埋设时的预期读者效果一致（回收方式和预期对不上 → 打回）
    - 状态迁移只能沿 已埋设→已推进→已回收/已废弃 方向；从已回收/已废弃回退 → 打回
    - 正文出现「像伏笔」的线索但 CHANGES 未声明且总览无此伏笔 → 打回，标注「疑似未登记伏笔，请补充设计或删除线索」
    - 伏笔埋设后 10 章未推进且未回收 → 警告「伏笔 vX 已埋设 N 章未推进」
    - 检测到旧格式伏笔（无 vX ID，如「优先级：核心/普通/彩蛋」写法）→ 警告「建议迁移到 vX 格式」，不打回
    - **双写一致性（v3.5.34）**：同一件事实有两份记录——`伏笔追踪/vID-*.md` 里的 `- 状态：` 和快照「## 伏笔状态」表的状态列。两处不一致 → 打回（`[伏笔双写] vX 档案状态「已埋设」与快照「已推进」不一致`）；只在一边登记（有档案没表行、有表行没档案）→ 警告。用 `apply-changes.js` 回写快照时两处自动一起改（v3.5.35）；手改的话两处一起改。档案里没写 `- 状态：` 的不比对。

**验收分级（能不人工就不人工，2026-10-10 老板定）**：
- **自动验收**（默认，无需人工）：① 脚本门禁：一致性 / 冲突 / 文本健康 / AI味 / 门禁报告完整性；② 单测 + 三个集成回归（CI 绿即过）；③ **AI 判层 → 双模型独立复核**：新上下文/另一模型独立跑同一章门禁，两份报告经 `compare-gate-reports.js` 比对——**完全一致即自动通过**（把 AI 判的正确性也自动化，不再靠单模型自觉）；④ **复核发现问题 → 修复后二次复核修正版**（硬规则）：验证修复到位+无新问题后方可判通过/同步，未二次复核不得放行（2026-10-12 老板定）。
- **人工验收（最后兜底）**：**仅当两模型报告出现结论分歧（= 歧义）**时升级人工——人工只裁定歧义，不是每章都审。报告缺项/不完整 = 流程问题 → **重跑复核**，不找人。
